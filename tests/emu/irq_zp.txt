# The interrupt calls C, so it goes through set_irq.
#
# The VSYNC interrupt reaches C: the flash step and the keyboard scan, and the
# PET's sound engine when this was written. cc65 compiles every C function
# against twenty bytes of shared zero-page scratch -- the C stack pointer,
# sreg, regsave, ptr1-4, tmp1-4 -- so a handler that calls C and does not put
# those back returns to a C function holding its own pointers rewritten. As a
# bare .interruptor this handler did exactly that.
#
# PLOT_TILE was C, which is how it showed: a tile whose base address was
# corrupted mid-loop wrote its three rows into the bitmap plane instead of the
# character plane, and the runs stayed behind the moving playfield for the rest
# of the game. The fix is cc65's own: set_irq installs the handler and the
# runtime's clevel_irq wrapper saves that zero page around the call.
#
# The renderer that draws the window now is C as well, and walking is what
# drives it hardest: twenty steps right, each loading the tiles it brings into
# view.
